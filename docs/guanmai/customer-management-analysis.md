## 四、业务逻辑分析

### 4.1 数据模型（核心字段）

```
商户 (Customer)
├── 账号层 (Account)
│   ├── 账户ID (KID)           — 唯一标识
│   ├── 登录账户               — 商户登录名
│   ├── 商户类型               — 店铺/个体/企业
│   ├── 密码/手机号/公司名
│   └── 状态: 冻结/白名单/审核
│
├── 店铺层 (Store)
│   ├── 店铺ID (SID)           — 唯一标识
│   ├── 店铺名/自定义编码
│   ├── 商户标签                — 分类标签（多选）
│   ├── 收货人/收货电话
│   ├── 地理标签                — 省-市-区三级
│   └── 门头照/营业执照
│
├── 结算层 (Settlement)
│   ├── 结算人/结算人电话
│   ├── 结算方式               — 先货后款/先款后货
│   ├── 账期方式               — 按周期/按单
│   ├── 日期维度               — 按下单日期/按收货日期
│   ├── 结款周期               — 日结/周结/月结
│   └── 起始日/结算日
│
├── 配置层 (Config)
│   ├── 分拣优先级
│   ├── VIP标识
│   ├── 报价单绑定              — 站点+报价单
│   └── 时价显示
│
└── 关联层 (Relations)
    ├── 从属站                  — 所属组织
    ├── 开户经理/销售经理
    └── 报价单关联
```

### 4.2 商户生命周期

```
新商户邀请（二维码/链接）
    ↓
注册 → 待审核 → 审核通过 → 正常运营
    ↓              ↓
  冻结          禁用/注销
```

### 4.3 关键关系

| 关系 | 说明 |
|------|------|
| 账户 : 店铺 | 1:N（一个账户可有多店铺） |
| 商户 : 报价单 | N:N（通过配置及关联绑定） |
| 商户 : 站点 | N:1（一个商户属于一个站点） |
| 商户 : 订单 | 1:N（通过 KID 关联） |
| 商户 : 结款周期 | 每个商户有独立结算配置 |

### 4.4 结款逻辑

观麦的结款配置非常精细：
- **结算方式**决定资金流方向（先货后款/先款后货）
- **日期维度**决定账单统计依据（按订单日还是收货日）
- **结款周期 + 起始日/结算日**决定账期计算
